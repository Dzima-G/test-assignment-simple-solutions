## Технологии
- **uv** - менеджер зависимостей.
- **FastAPI** - фреймворк для построения быстрых REST API.
- **PostgreSQL** - реляционная база данных.
- **SQLAlchemy** - работа с данными и моделями.
- **Alembic** - миграции БД.
- **Docker** - контейнеризация приложения.
- **Redis** - быстрое in-memory хранилище, используется как брокер сообщений для Celery.
- **Celery** - система для обработки фоновых задач, использующая Redis в качестве брокера сообщений.

## Переменные окружения

Образ считывает настройки из переменных окружения.
Создайте файл `app/core/.env` (пример `.env.example`) и запишите туда данные в формате: `ПЕРЕМЕННАЯ=значение`.

- **`DEBUG`** - настройка для включения отладочного режима.  
  Принимает значения `TRUE` или `FALSE`.
- **`POSTGRES_USER`** - имя пользователя PostgreSQL.  
  Используется при первом запуске для создания пользователя БД.
- **`POSTGRES_PASSWORD`** - пароль пользователя PostgreSQL.  
  Используется при первом запуске для создания пароля пользователя БД.
- **`POSTGRES_DB`** - название базы данных PostgreSQL.  
  Используется при первом запуске для создания БД.
- **`DB__URL`** - адрес для подключения к базе данных PostgreSQL.  
  Другие СУБД не поддерживаются.  
  [Документация SQLAlchemy](https://docs.sqlalchemy.org/en/21/core/engines.html)

## Design decisions
1. В качестве менеджера пакетов выбран uv. Позволяет фиксировать зависимости локально, в docker, в CI - у всех одинаковые версии.
2. Без глобальных переменных - настройки создаются через `get_settings()` с использованием `@lru_cache`, приложение через фабрику `create_app()`. Подключение к БД создается через `lifespan`, хранится в `app.state`. Так объекты не создаются при импорте модулей.
3. Engine и фабрика сессий в классе `Database`. Класс не зависит от FastAPI и конфига.
4. Для подключения к БД используется `DB__URL`, для создания при первом старте отдельные `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB`. Так удобней в проде при развертывании в кластере k8s, где адрес бд приходит готовый из secrets.
5. Dockerfile - c двумя стадиями dev и prod. Dev — dev-зависимости, `--reload`, код подключается через volume. Prod — без dev-зависимостей, код копируется в образ.
